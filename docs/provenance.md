# Speech System Provenance

Tongues is a distinct speech system descended from and compatible with Coqui
TTS and Piper work. It is neither an original inventor of the neural
architectures it implements nor merely a provider-branded framework translated
to Rust.

The distinction is architectural. Tongues defines a backend-neutral synthesis
contract, capability negotiation, acoustic-model/vocoder composition, one
resident Burn/ONNX/StyleTTS2 runtime, indexed CPU/CUDA policy, bounded server
admission, a non-executing checkpoint importer, a checksum-verified offline
model store, shared native audio/DSP, and its own language/variety,
pronunciation, phoneme, phone, and Common Phone representations. Its public
concepts are model package, language, variety, speaker, style, capability,
acoustic output, and waveform rather than a particular upstream Python class.

That original machinery coexists with deliberate compatibility work.

## What Tongues Reuses

Tongues currently uses or targets:

- published Coqui SpeedySpeech, FastPitch, Tacotron2-DDC, Glow-TTS, HiFi-GAN
  v2, MultiBand-MelGAN, and VITS weights and configurations;
- the MIT-licensed Descript Linda Johnson MelGAN checkpoint and its published
  generator tensor layout;
- Coqui checkpoint tensor layouts, token contracts, defaults, and intermediate
  inference behavior;
- golden fixtures generated by pinned Coqui reference runs;
- VITS-family ONNX voices and configuration files distributed through Piper;
- established SpeedySpeech, FastPitch, Tacotron, Tacotron 2, Capacitron,
  Glow-TTS, HiFi-GAN, VITS, and StyleTTS2 architectures.

Tongues therefore describes these implementations as native compatibility
implementations, not as novel synthesizer architectures.

## Naming Boundary

Catalog identity is split into separate concerns:

| Field | Meaning | Examples |
|---|---|---|
| `architecture` | Provider-neutral neural family | `speedy-speech`, `fastpitch`, `hifigan-v2`, `vits`, `styletts2` |
| `provenance.format` | Upstream serialization/package format | `coqui-pytorch-zip`, `onnx` |
| `provenance.source` | Exact distribution or model source | Coqui release or Piper voice URL |
| `compatible_with` | External checkpoint/config/runtime contracts | `coqui-tts-v0.6.1`, `piper-onnx`, `piper-voice-config` |
| `aliases` | Stable model lookup compatibility | `coqui-speedy-speech`, `coqui-vits-vctk` |

Provider names belong in provenance, compatibility, import adapters, cache
paths that identify an upstream distribution, and legacy aliases. They do not
define the neural architecture.

## Source-Relationship Classifications

Every implementation that follows an external system should eventually carry
one of these evidence-backed classifications:

| Classification | Required evidence |
|---|---|
| `paper-derived` | Paper/specification citations and an implementation history that did not use upstream source expression |
| `behaviorally-reimplemented` | Pinned black-box/reference behavior, fixtures, checkpoint/config contracts, and no copied source expression |
| `source-adapted` | Exact upstream repository, revision, and source files; applicable copyright/license notices in every adapted file |
| `audit-required` | Relationship is known but the evidence is insufficient to choose one of the preceding classifications |

Using familiar algorithm names, tensor paths, configuration keys, or behavior
does not by itself determine copyright provenance. Conversely, translating or
closely adapting source expression is not made independent merely by changing
the programming language.

An audit that finds source adaptation must update this ledger, add a per-file
notice naming the upstream file and revision, and apply that upstream license's
redistribution requirements. An audit that concludes behavioral
reimplementation should retain its comparison evidence.

## Licensing Is Layered

The repository's [`LICENSE`](../LICENSE) covers Tongues-authored source under
MIT. It does not relicense third-party source, weights, voice packages,
datasets, or generated material.

In particular:

- Coqui TTS `v0.6.1` source is MPL-2.0. It is not Apache-2.0.
- The SpeedySpeech, FastPitch, HiFi-GAN v2, and VCTK VITS registry evidence is
  `TBD` or blank, so those weight archives are `NOASSERTION`. The
  MultiBand-MelGAN registry entry explicitly declares `MPL`, and its catalog
  entry retains that evidence as `MPL-2.0`.
- The pinned Descript Linda Johnson MelGAN checkpoint is covered by its
  upstream repository's MIT license.
- Piper source is MIT, but each Piper-distributed voice has its own license.
- A paper's availability does not grant a license to copy a project's source
  implementation or redistribute a trained model.
